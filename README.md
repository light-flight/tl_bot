# Telegram → Linear

Бот сидит в группе. Когда его отмечают, он создаёт issue в Linear и отвечает ссылкой.

Первая строка после `@бот` — название, остальные строки — описание. Ответ на другое сообщение попадает в описание; если в самом сообщении названия нет, оно берётся из первой строки того сообщения. Отметка другого человека назначает исполнителя. Команда и проект берутся из настроек этого чата.

## Настройка

В BotFather оставьте privacy mode включённым: бот видит упоминания, ответы себе и команды. Админом в группе его делать не нужно.

Переменные процесса:

- `TELEGRAM_BOT_TOKEN` — токен BotFather
- `SETTINGS_KEY` — `openssl rand -base64 32`. Этим ключом шифруются настройки чатов. Если он не подходит к уже записанному файлу, бот не стартует
- `DATABASE_PATH` — файл настроек. Локально `data/settings.sqlite`, в Kamal `/data/settings.sqlite`
- `PORT` — `3000`
- `TELEGRAM_WEBHOOK_SECRET` — длинная случайная строка, ей же бот регистрирует webhook
- `WEBHOOK_URL` — `https://<домен>/telegram/webhook`

Сразу после добавления в группу бот пишет карточку с кнопкой «Настроить». Её нажимает администратор чата. Дальше мастер виден только ему:

1. `/key` — personal API key из Linear. Команда скрытая: её не видно остальным. Бот удаляет сообщение и больше не показывает ключ.
2. Команда Linear — кнопкой.
3. Проект — кнопкой или «Без проекта».
4. `/assignees` — `telegram_username:linear_email` или `telegram_id:linear_user_id`, через запятую. Можно нажать «Без карты».

Обычное сообщение с ключом бот не сохраняет. Если его можно удалить, удаляет и просит прислать ключ командой `/key`.

`/settings` показывает команду, проект и число соответствий. Сам ключ в ответе не появляется. Пока мастер не подтверждён, упоминания идут в уже сохранённые настройки чата.

Если человека нет в карте и совпадение не однозначное, задача создаётся без исполнителя. Запись в карте, которой нет в Linear, не подменяется угадыванием и не заменяет уже сохранённую карту.

В группе: `@бот Починить логин` или `@бот @ivan Починить логин`. В личке `/start` отвечает короткой справкой. Ключ из лички к чату не привязывается.

## Kamal

Один контейнер. Настройки чатов лежат в volume `tl_bot_data` и переживают деплой. Нужен Kamal 2.8 или новее (`kamal version`): он сам поднимает локальный registry на `localhost:5555` и по SSH прокидывает его на сервер. Логин и пароль registry не нужны.

IP сервера, `proxy.host` и `WEBHOOK_URL` лежат в `config/deploy.production.yml`. Этот файл в git не попадает. Скопируйте [`config/deploy.production.yml.example`](config/deploy.production.yml.example) и впишите свои адреса. DNS хоста должен смотреть на сервер. Для ARM-сервера поменяйте `builder.arch` на `arm64` в [`config/deploy.yml`](config/deploy.yml).

Секреты лежат в `.kamal/secrets` (файл в git не попадает) и подхватываются как shell:

```bash
TELEGRAM_BOT_TOKEN=123:abc
SETTINGS_KEY=base64-from-openssl-rand
TELEGRAM_WEBHOOK_SECRET=long-random-string
```

`SETTINGS_KEY` после первого запуска менять нельзя: старый файл настроек перестанет читаться, и бот не стартует. `TELEGRAM_WEBHOOK_SECRET` — любая длинная случайная строка. Kamal передаёт её в контейнер, бот сам вызывает `setWebhook`.

```bash
kamal setup -d production
kamal deploy -d production
```

Без `-d production` Kamal не знает сервер.

### Перенос на другой сервер

Сначала разверните бота на новой VPS с тем же `SETTINGS_KEY`. В `config/deploy.production.yml` к этому моменту уже записан новый IP. Потом снимите базу со старого сервера и залейте её на новый:

```bash
script/kamal-data pull 203.0.113.5
script/kamal-data push
```

`pull` останавливает бота на указанном хосте, копирует `settings.sqlite` в `data/migration/settings.sqlite` и снова его запускает. Повторный `pull` не затирает уже снятый файл без `--force`. `push` спрашивает подтверждение, останавливает бота на сервере из конфига, кладёт файл в volume и запускает бота. Предыдущий файл на новом сервере остаётся в `/data/settings.sqlite.bak`.

Дальше переключите A-запись домена и выключите старый сервер. Webhook бот регистрирует сам, при старте он вызывает `setWebhook` на тот же `WEBHOOK_URL`.
